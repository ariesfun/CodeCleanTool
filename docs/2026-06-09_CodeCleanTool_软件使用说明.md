## 一、软件简介

CodeCleanTool 是一款面向 C++/Qt 开发者的**源代码清理与打包工具**。在交付、归档、外发工程前，自动识别并清理编译产物、IDE 缓存、临时文件等无关内容，保留核心源码和必要资源，一键生成仅含源码的 7z 压缩包。

**核心能力：**
- 自动识别 36 种清理目标（编译产物、IDE 缓存、临时文件、构建目录）
- 智能保留 22 类源码文件（C++/Qt/CMake/文档）
- 内置规则覆盖 IDE 缓存、编译产物、调试文件、临时文件、构建目录等常见工程垃圾，并支持自定义增删规则
- 配置与主题偏好自动保存到程序目录，重启后自动恢复
- 所有操作可预览、可确认、可撤销前取消
- 异步执行，不阻塞界面

## 二、安装与启动

### 2.1 环境要求

| 组件 | 最低要求 |
|------|---------|
| 操作系统 | Windows 10/11 64-bit |
| 运行时 | Visual C++ 2019 Redistributable |
| 依赖 | Qt 5.15.2 DLL（已随程序部署） |

### 2.2 启动方式

**Release 版本（推荐）：**
直接双击 `Release/CodeCleanTool.exe` 启动。

**首次运行前需部署 Qt 依赖：**
```
windeployqt Release/CodeCleanTool.exe --no-translations --no-compiler-runtime
```

> 注意：Ela 框架原作者建议使用 Release x64 编译，以保证 UI 渲染性能。Debug 版本仅用于开发调试。

## 四、扫描——查找可清理内容

### 4.1 选择目录

**方式一：手动输入**
在顶部路径输入框中直接输入或粘贴工程根目录路径。

**方式二：浏览选择**
点击 **"浏览"** 按钮 → 在弹出的文件夹选择对话框中导航到目标工程目录 → 确认。

### 4.2 执行扫描

点击底部状态栏的 **"扫描"** 按钮（🔍）。

> 扫描范围**包含隐藏目录与隐藏文件**（例如 Visual Studio 生成的 `.vs` 目录带隐藏属性），因此 IDE 缓存能被正常识别。`Thumbs.db` 等系统隐藏文件若命中清理规则同样会列出。`.git`/`.svn` 是否跳过由设置页的"排除版本控制目录"开关控制。
>
> 扫描范围**只由规则决定，不参考工程的 `.gitignore`**——`.gitignore` 里列的通常正是构建垃圾，恰恰是本工具要清理的对象。
>
> **切回扫描页会自动重新扫描一次**（前提是路径栏已有目录）。因此在"规则"页增删或修改规则后，切回"扫描"页即可立刻看到结果变化，无需再手动点一次扫描。

扫描过程中：
- 状态栏显示 "正在扫描..."
- 进度条实时更新扫描进度
- 统计信息显示 "扫描中..."

扫描完成后：
- 文件列表表格展示所有匹配清理规则的文件
- 统计信息更新：`共 N 项 | 待清理 N 项 | 可释放 X MB`
- 状态恢复为 "就绪"
- **瘦身统计环形图**自动显示在右侧「瘦身统计」Dock 面板中（与上方「文件详情」Dock 并列，均停靠在窗口右侧），包含：
  - 甜甜圈环形图：橙红色弧段 = 可清理比例，中心显示百分比
  - 右侧图例：原项目大小 / 可释放空间 / 清理后剩余
  - 清理完成后环形图自动刷新

### 4.3 表格列说明

| 列名 | 说明 | 示例 |
|------|------|------|
| 文件名 | 匹配项的名称，**前面带图标**：📁 = 目录，📄 = 文件 | `vc143.pdb` |
| 路径 | 完整路径 | `D:/Project/x64/Debug/vc143.pdb` |
| 大小 | 大小（带单位） | `12.5 MB` |
| 修改时间 | 最后修改时间 | `2026-06-09 14:30:00` |
| 类型 | 分类标签（6色） | `IDE缓存` / `编译产物` / `调试文件` / `临时文件` / `构建目录` / `其他` |
| 命中规则 | 触发清理的规则名 | `*.pdb` |

> **名称列图标的用途**：清理目标既有文件也有目录（如 `.vs/`、`build/`）。图标让你一眼分辨——
> 目录被删除时，其下所有内容会一并删除。

- **列宽可拖拽调整**：鼠标移到表头列边界，左右拖动
- **点击表头排序**：按文件名/大小/时间/规则排序。排序是**两段式**的 —— 先按类型分组（编译产物、构建目录等大件排在最前），同类型内再按你点击的那一列排。所以点"大小"升序时，最前面仍可能是某个体积不大的编译产物，而不是全表最小的那一项
- **首列复选框**：勾选/取消勾选待清理项

> **已知限制：** 文件列表暂不支持搜索或过滤，只能靠排序定位。列表很大时，建议先在规则页收窄扫描范围，而不是在大列表里翻找。

### 4.4 全选/反选

路径栏右侧的两个快捷按钮：
- **全选**：勾选所有扫描结果
- **反选**：取消所有已勾选项（全部取消勾选）

## 五、清理——删除选中文件

### 5.1 勾选目标

在文件列表中，勾选首列复选框选择要删除的文件/目录。

> **提示：** 可使用"全选"按钮快速勾选全部，再手动取消不需要删除的个别项。

### 5.2 执行清理

1. 确保至少勾选了一个文件
2. 点击底部状态栏的 **"清理"** 按钮（🗑）
3. 弹出确认对话框：`将删除 N 个文件/目录，此操作不可恢复，确定继续？`
4. 点击 **"确认清理"** 确认执行，**"取消"** 取消操作

清理过程中：
- 进度条显示清理进度
- 状态栏显示 "正在清理..."

清理完成后：
- 已删除的项从表格中移除
- 统计信息自动刷新
- 状态栏显示 `清理完成：成功 N，失败 M`

> ⚠️ **警告：** 清理操作直接删除文件，不可恢复。请在执行前确认勾选的确实是可以删除的内容。

## 六、打包——生成源码压缩包

### 6.1 打包逻辑

打包生成的是**纯源码压缩包**：整个工程目录，**排除掉已勾选的待清理项**。语义约定：

- 勾选 = 待清理 → 不打包
- 未勾选 = 保留 → 打包内容

文件列表中显示的只是命中的清理目标，源码文件（`.cpp`/`.h`/`CMakeLists.txt` 等）根本不在此列。
因此"未勾选"的含义是**不排除**，而不是"构成打包清单"——未勾选的文件连同全部源码一起进包。

> 反选（全部取消勾选）后打包 = 不排除任何项 = 打包整个目录。

### 6.2 执行打包

1. 确保路径输入框中有有效的工程目录
2. 点击底部状态栏的 **"打包"** 按钮（📦）
3. 等待打包完成

打包过程中状态栏显示 "正在打包..."，进度条实时更新。

打包完成后状态栏显示 `打包完成: D:/Project/output/项目名_20260609_143000_source.7z (15.3 MB)`。

### 6.3 包名规则

默认包名格式：`{项目名}_yyyyMMdd_hhmmss_source.7z`（含日期与时分秒，避免同一天多次打包重名）

可在**设置页**中自定义包名模板；模板留空时回退到上面的默认格式。模板支持的占位符：

| 占位符 | 展开为 |
|--------|--------|
| `%Project` | 项目名（取源码目录的目录名，取不到时退化） |
| `%YYYY` | 四位年份 |
| `%MM` | `%HH` 之前 = 月份；`%HH` 之后 = 分钟 |
| `%DD` | 日期 |
| `%HH` | 小时 |
| `%SS` | 秒 |

> **注意 `%MM` 的歧义：** 它以 `%HH` 为分界——出现在 `%HH` 之前按"月"展开，之后按"分"展开。例如 `%YYYY%MM%DD_%HH%MM%SS` 会展开为 `20260609_143000`。未识别的占位符原样保留。

## 七、规则管理

### 7.1 打开规则页

点击左侧导航栏的 **"规则"** 页。

### 7.2 规则分区布局

规则页面分为上下两个区段，使用 QGroupBox 分组框清晰分隔：
- **上方"清理规则（N 条）"** — 列出所有清理规则，红色标签标识
- **下方"保留规则（N 条）"** — 列出所有保留规则，绿色标签标识
- 标题中的条数随添加/移除操作动态更新

各区段内使用独立表格，包含三列：

| 列 | 说明 |
|----|------|
| 模式 | glob 模式（如 `*.obj`、`build/`） |
| 适用对象 | **文件夹图标** = 目录规则，匹配【目录名】，以 `/` 结尾（如 `.vs/`）<br>**文件图标** = 文件规则，匹配【文件名】，需带通配符（如 `*.obj`）<br>鼠标悬停可看到同样的说明 |
| 操作 | "移除规则"按钮 |

> **为什么要区分这两者：** 同一类文件可能同时被目录规则和文件规则覆盖。
> 例如与 `.db` 有关的有两条——`.db/`（目录规则，管名为 `.db` 的目录）与 `*.db`（文件规则，管 `.db` 文件）。
> 移除规则前先看这一列的图标，才能确认移除的是哪一条。详见 §7.4。

### 7.3 添加规则

1. 在"输入规则模式"文本框中输入 glob 模式
   - 文件规则：`*.tmp`、`*.log`
   - 目录规则：`build/`、`Debug/`（以 `/` 结尾即视为目录规则）
2. 从下拉框选择类型：**清理规则** 或 **保留规则**
3. 点击 **"添加"** 按钮
4. 新规则立即生效，本次程序运行期间持续有效，改完直接点"扫描"即可，无需重启

> **⚠️ 文件规则必须带通配符。** 输入 `.exe` 只能匹配文件名恰好是 ".exe" 的文件，
> **不会**匹配 `tool.exe`，正确写法是 `*.exe`。
>
> 为免踩这个坑，程序会自动把「点 + 扩展名」的裸写法补成通配形式（`.exe` → `*.exe`），
> 并在日志页记录一条 `规则 .exe 已自动补全为 *.exe`，便于你核对实际生效的模式。
> 例外：`.gitignore`、`.gitattributes` 这类整体就是文件名的写法不会被补全。

### 7.4 移除规则

在规则表格中点击目标规则行的 **"移除规则"** 按钮，该规则立即从列表移除。标题栏条数同步更新。

> **⚠️ 同一类文件可能被多条规则覆盖，只移除一条未必够。**
>
> 例如与 `.db` 有关的内置规则有**两条**：
> - `.db/` — 目录规则，匹配名为 `.db` 的**目录**（"适用对象"列为**文件夹图标**）
> - `*.db` — 文件规则，匹配 `.db` **文件**（"适用对象"列为**文件图标**）
>
> 若你的目的是「不再清理 `.db` 文件」，需要移除的是 **`*.db`**；只移除 `.db/` 不会影响
> 文件匹配，`.db` 文件仍会被扫出。按"适用对象"列的图标即可区分两者。
>
> 同理，若某类文件移除规则后仍出现在扫描结果中，请按上述思路检查是否还有其它规则命中它
> （可对照"命中规则"列显示的规则名）。

> 注意：内置规则（预置的 36 条清理 + 22 条保留）与自定义规则统一管理，均可移除。如需恢复内置规则，需重新启动程序。

## 八、日志查看

### 8.1 打开日志页

点击左侧导航栏的 **"日志"** 页。

### 8.2 日志列表

日志以表格形式展示，包含四列：

| 列 | 说明 |
|----|------|
| 时间 | 日志产生时间（`hh:mm:ss` 格式） |
| 级别 | INFO / WARN / ERROR |
| 模块 | 日志来源模块（如 `MainPresenter`） |
| 内容 | 日志详细消息 |

### 8.3 级别过滤

顶部过滤按钮栏，点击可按级别筛选：

| 按钮 | 筛选效果 |
|------|---------|
| **全部** | 显示所有级别日志 |
| **INFO** | 仅显示 INFO 日志 |
| **WARN** | 仅显示 WARN 日志 |
| **ERROR** | 仅显示 ERROR 日志（红色高亮） |

**日志着色规则：**
- ERROR 级别 → 红色字体（RGB 220, 50, 50）
- WARN 级别 → 橙色字体（RGB 200, 140, 0）
- INFO 级别 → 默认颜色

### 8.4 导出日志

点击 **"导出"** 按钮 → 选择保存路径和文件名 → 日志内容导出为 `.log` 或 `.txt` 文件。

> 导出文件为 **UTF-8 编码**，可直接用 VS Code、记事本等工具打开，中文不会乱码。

### 8.5 清空日志

点击 **"清空"** 按钮 → 清空当前日志列表中所有条目（不影响日志文件的持久化存储）。

## 九、设置配置

### 9.1 打开设置页

点击左侧底部导航的 **"设置"** 页。

### 9.2 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| **打包输出目录** | 7z 压缩包的输出路径，留空则输出到源码目录的 `../output` | 留空（即 `../output`） |
| **包名模板** | 压缩包命名格式，支持 `%Project`/`%YYYY`/`%MM`/`%DD`/`%HH`/`%SS` 占位符（详见 §6.3），留空则用默认命名 | `项目名_yyyyMMdd_hhmmss_source` |
| **排除版本控制目录** | 扫描和打包时跳过 .git/.svn 目录 | 开启 |
| **清理完成后自动打包** | 清理结束后是否自动触发打包 | 关闭 |
| **7z 路径** | `7z.exe` 可执行文件路径（打包用），可点击"浏览"选择 | 留空（自动检测：已知路径 → 注册表 → PATH） |

> 以上配置项保存在**程序所在目录（exe 同级）**的 `config.ini` 中，程序启动时自动加载，**重启后自动恢复**；保存与提示行为见 §9.3。

### 9.3 保存设置

修改配置后，点击 **"保存设置"** 按钮，配置会写入**程序所在目录**（exe 同级）下的 `config.ini`：

- 保存成功 → 页面底部提示 **"设置已保存"**
- 保存失败（例如程序放在只读目录）→ 提示 **"设置保存失败（程序目录不可写？）"**

配置在程序启动时自动加载，**重启后设置自动恢复**，无需重新填写。如需恢复出厂默认值，关闭程序后删除该 `config.ini` 再启动即可。

## 十一、典型工作流

### 交付前清理打包流程

```
1. 启动 CodeCleanTool
2. 在"扫描"页输入工程根目录，或点击"浏览"选择
3. 点击"扫描"按钮，等待扫描完成

```

## 十二、常见问题

### Q: 扫描结果为空？
- 检查目录路径是否正确
- 确认目录下存在匹配清理规则的文件
- 查看"规则"页确认清理规则未被全部删除

### Q: 清理时报错？
- 文件可能正被其他程序占用，关闭对应程序（如正在编译的 IDE）后重试
- 只读文件会自动处理（取消只读属性后删除），无需手动修改属性
- 提示无法删除的目录，通常是目录内仍有被占用的文件
- 清理是**幂等**操作：若目标已不存在（例如已随上级目录一并删除），按成功处理，不会报错

### Q: 移除了某条规则，为什么对应文件仍被扫描出来？
- **同一类文件可能被多条规则覆盖**。例如与 `.db` 有关的有两条：`.db/`（目录规则）与 `*.db`（文件规则）。只移除其中一条，另一条仍会命中
- 看规则页的 **"适用对象"列图标**：文件夹 = 目录规则，文件 = 文件规则。要"不再清理 `.db` 文件"应移除带**文件图标**的 **`*.db`**，而不是 `.db/`
- 也可看文件列表的 **"命中规则"列**，它显示该文件具体被哪条规则命中，据此定位该移除哪条

### Q: 新增了 `.exe` 规则，为什么没生效？
- **文件规则必须带通配符**：`.exe` 只能匹配文件名恰好是 ".exe" 的文件，不会匹配 `tool.exe`，正确写法是 `*.exe`
- 程序会自动补全这类裸写法（`.exe` → `*.exe`），并在日志页记录 `规则 .exe 已自动补全为 *.exe`，可据此核对实际生效的模式

### Q: 打包时报错？
- 确认系统已安装 7-Zip，且 `7z.exe` 在 PATH 中
- 检查输出目录的写入权限

### Q: 如何恢复误删的规则？
- 重启程序即可恢复全部内置规则
- 自定义规则需重新添加
